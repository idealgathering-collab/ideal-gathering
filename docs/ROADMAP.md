# Roadmap

Phases express dependencies and readiness, not arbitrary dates. This is direction, not approval to implement every item.

## Phase 0 — Durable operating workflow
Repository instructions, reality-first docs, decision log, task template and resumable checkpoints. Exit: files reviewed and saved in GitHub; next task has a clear specification and approval state.

## Phase 1 — Beta foundations and correctness
Validate current auth/beta/owner/venue boundaries, schema/type consistency, onboarding persistence, profile data ownership and trust/privacy.
First proposed implementation discussion: owner bootstrap/helper mismatch and type reconciliation (see [DATABASE](DATABASE.md)). Follow with profile/onboarding save semantics and existing gate/navigation issues.
Exit: agreed critical access paths and data behavior pass relevant checks; unresolved risks recorded.

## Phase 2 — Core small-gathering loop
Refine profiles/social signals, gathering creation/discovery/joining, venue support and Cell group composition through small approved specs. Resolve 2–5 target versus current limits as a product decision.
Exit: agreed beta journeys work with representative users, missing-data cases, capacity/privacy safeguards and useful feedback.

## Phase 3 — Beta learning and refinement
Use minimal, consent-aware feedback to evaluate comfort, participation and group quality; improve reliability, accessibility, language coverage and operational support. No arbitrary engagement/popularity targets.
Exit: evidence supports expansion and outstanding trust issues are understood.

## Phase 4 — Later product capabilities and research
Live Gathering, Emergency Button, Community Aid and advanced Brain research. Each requires its own product, privacy, safety, feasibility and operating-model discussion before an implementation spec. Do not prebuild infrastructure now.
