# IG-008 — Venue Dashboard Value Layer

## Status
Approved for implementation planning.

## Goal
Finish the venue side around the strongest commercial proof: Ideal Gathering brought real people into this venue.

## Principle
Do not rebuild the existing venue dashboard. Audit it and add the missing value layer.

## Preserve
Venue registration, venue auth, venue dashboard, businesses, venue tables, menu items, venue-linked gatherings, approval/access states, and owner venue preview.

## V1 value metrics
Where supported by real data:
- gatherings hosted
- upcoming gatherings
- completed gatherings
- checked-in visitors
- distinct visitors
- first-time visitors
- repeat visitors
- most active days/times
- popular gathering categories
- recent gathering activity

## Attribution rule
Use real attendance/check-in data. Do not claim revenue, purchases, or exact customer value unless measured.

## Workflow to verify
1. Venue registers.
2. Venue waits for required approval/beta access.
3. Venue accesses dashboard when allowed.
4. Venue completes business profile.
5. Venue manages currently supported tables/menu.
6. Venue can be selected as gathering location.
7. Gathering takes place there.
8. Real attendance flows into analytics.
9. Venue sees clear evidence of activity generated by Ideal.

## Security/correctness
Move venue access protection to a robust route/server-authorized boundary where current implementation relies too heavily on UI gating.

## Acceptance criteria
- Venue users cannot access another venue's private data.
- Dashboard shows real gathering/visitor data.
- First-time/repeat visitor logic is defined and tested.
- Registration-to-dashboard journey works end to end.
- Existing venue management remains functional.
- Owner/admin oversight remains compatible.

## Out of scope
Billing, subscriptions, paid promotion, sponsored ranking, campaign budgets, ad marketplace.
